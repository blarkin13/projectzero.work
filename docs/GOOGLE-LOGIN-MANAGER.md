# Portfolio Google login manager

Owner-only dashboard: `/integrations/google-login`, linked from Integrations and Chamber of Secrets.

- A per-business registration card lists the reviewed OAuth origin, callback, Worker and binding names. SiteAPT currently uses its older account.statatlas.app callback; this is intentional until the callback migration is verified. Project Zero remains owner-only.
- Create one Google Auth Platform Web application client per business, configure branding and consent, register the exact callback, and download its client JSON. Google approval, consent and the actual end-to-end sign-in cannot be automated via the manager.
- Import the client JSON using the protected form. Only the minimal credential pair and the reviewed redirect URI are stored, encrypted with the existing Chamber key, with an audit event. No secret values are displayed. For an imported credential with no deployed pair, the explicit new-install action verifies that neither the intended bindings nor common aliases exist, then uses Cloudflare bulk secret patch to install both together. It verifies the two secret binding names afterwards. It refuses to replace or repair existing/partial pairs. The Worker deployment token must have Workers Scripts Edit; no new broad token is required. Do not reuse credentials between businesses.
- The redirect probe never follows Google or other redirects or stores tokens, state, or client IDs. It checks the exact Google authorization endpoint, the callback and minimum OAuth parameters. It cannot establish that token exchange, audience, consent or session works. Use the individual browser links for real end-to-end testing. The existing 6-hour schedule refreshes the private metadata snapshot; only consecutive definitive configuration failures create a deduplicated P0 investigation task. Unreachable or indirect redirects are unverified, not treated as confirmed failures.
- For an existing project, the setup task includes the reviewed route; for future active tracker projects, the provisioning task requests reviewed domain and callback, separate Google client, secure session implementation, tests and authorized release. Arbitrary Worker names/URLs are deliberately not accepted by the credential installer.
- No schema migration or new cron is needed. No existing app login, customer access policy, credentials or production routes are changed by deploying the manager alone. Rotation of deployed credentials is a separate reviewed operation.
