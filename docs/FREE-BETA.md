# Free beta (owner-authorized, no pricing)
 
The public site asks visitors to email contact@projectzero.work to request a free beta invitation. Approved testers enter a single-use invite at https://account.projectzero.work/auth/signup; the existing sign-in form also works for registered users. The account service hosts real email-verified accounts, isolated from the owner's dashboard and its portfolio data. No card, Stripe binding, subscription, billing, auto-renewal, provider credential, financial metrics import or AI execution is enabled. The fictional demo remains independent; all paid offerings require explicit future opt-in.

## Beta functionality
- A single mailbox-verified owner per workspace; no email-only linking to previously authorized Google identities. Eight-digit single-use code, ten-minute expiry, five attempts, browser-bound challenge, 12-hour hashed opaque session, same-origin writes and logout.
- Three persistent projects, generated project-specific instructions, and 50 roadmap tasks per project (priority, notes, revision-safe status updates). Copy instructions for optional assistants. Direct assistant API/key creation and external integrations stay disabled in the invite-only beta pending verification.
- User-directed data export and permanent live-account deletion require the authenticated workspace owner; deletion also requires a recent session and explicit confirmation. Backups/security counters expire according to their retention policies. Public privacy and terms are canonical on www.projectzero.work. Support and feedback use contact@projectzero.work.
- Cap at 100 concurrent registered beta accounts. Turnstile challenges use the exact account hostname and action. Cloudflare per-IP rate limiting plus atomic D1 counters cap email sends at 3 per email/day, 8 per IP/day, 30/day globally and 300 per calendar month; failed delivery may still consume budget. Sender is signin@auth.projectzero.work using the Cloudflare sending subdomain, reply-to contact@projectzero.work. Daily maintenance and opportunistic cleanup remove stale sign-in challenges, counters, expired/revoked sessions and consumed OAuth state.

## Configuration and rollout
- Apply additive migration schema/migrations/002-free-beta.sql ONLY to COMMERCIAL_DB after validating current schema. Apply 003-beta-invitations.sql once after 002. Verify foreign keys and no accidental customer records.
- Account hostname is account.projectzero.work; independent of www, apex/owner and dashboard. The owner signs in at https://account.projectzero.work/auth/login using the configured Google OAuth identity. The owner-only /admin/beta UI issues and revokes personal, email-bound invitations; only a hash is stored, the code is shown once, and it expires after 14 days. Reissuing revokes previous unused invitations; redemption is atomic with account provisioning after email verification. Registered testers retain access without another invitation. Google sign-in is limited to the configured owner email and pins the verified Google subject; paid commercial Google mode remains disabled. Use CUSTOMER_ACCESS=beta, EMAIL_LOGIN_MODE=invite_only, GOOGLE_LOGIN_MODE=owner_beta, OWNER_EMAIL, PZW_GOOGLE_CLIENT_ID, PZW_GOOGLE_CLIENT_SECRET and an independently generated GOOGLE_OAUTH_STATE_KEY secret, a managed Turnstile site key restricted to account.projectzero.work, TURNSTILE_SECRET as a Worker secret (never commit it), sender-restricted BETA_EMAIL binding, BETA_AUTH_LIMIT 12 requests per IP / 60 seconds, and the dedicated commercial D1 binding. The daily cron runs authentication cleanup only. Keep workers.dev and preview URLs disabled. No additional service bindings.
- The code is fail-closed without exact beta bindings; paid access is not enabled. Verify both active Worker source and configuration before and after release; preserve public landing service binding for the guide sitemap and analytics consent. No changes to the private dashboard's Access controls or databases.
- Production email sending domain must have DNS status ready. Email usage is capped independently; existing shared account plan/quota and other projects' email usage must be monitored. No new paid plan is required.
- Automated tests simulate the actual Worker HTTP requests over SQLite with a mocked email send and Siteverify, exercising consent, one-use codes, cross-tenant requests, wrong/expired codes, replay, quotas, export/delete, CSRF, and persistent roadmap.
